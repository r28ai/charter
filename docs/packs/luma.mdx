Luma runs event pages and the calendars that list them. This API is how a
program does what an organizer does in the app: create and update events, add
and approve guests, issue ticket types and coupons, email the guest list, and
manage the calendar's contacts, tags, admins and memberships.

The pack was drafted from Luma's own
[OpenAPI document](https://public-api.luma.com/openapi.json) by
`scripts/openapi_to_pack.py`, so every parameter, enum member and description
is Luma's, word for word. What a spec cannot carry — the rules Luma states in
prose, the sentences a blank parameter needed, the limits below — was added in
review.

## Authenticating

{/* generated:auth start — do not edit by hand; run scripts/generate_pack_docs.py */}
**Get a key:** at [luma.com/calendar/manage/api-keys](https://luma.com/calendar/manage/api-keys) choose the calendar and generate a key — it reaches that calendar only, and the API needs a Luma Plus subscription — then `export LUMA_API_KEY=…`.

This pack takes an API key in `x-luma-api-key`, and [`configure()`](/reference/configuration#configure) is optional when `$LUMA_API_KEY` is set.

That key serves every call the process makes. For an application whose users each connect their own account, hand [`configure()`](/reference/configuration#configure) a `credential_provider` instead — a [`SubjectProvider`](/reference/credentials#subjectprovider) that answers per user — and each call carries the credential of the user [`use_subject`](/reference/credentials#use_subject) names. [Your users' accounts](/auth/your-users) says how each pack's users connect.
{/* generated:auth end */}

A calendar key reaches the calendar it was made on and nothing else, so the
`calendars_*` tools act on that calendar and only `calendars_update` asks for its
ID.

An organization key reaches the `organizations_*` tools. Where Luma documents
choosing one of the organization's calendars — approving or rejecting a
submission — it is a header, and which calendar a call acts on is your decision,
not the model's, so pass it per call rather than as an argument:

```python
await luma.calendars_events_approve.ainvoke(
    {"calendar_event_id": "calev-..."}, headers={"x-luma-calendar-id": "cal-..."}
)
```

### Paging through a list

A cursor belongs to the tool that returns it, so it is declared on that tool's builder call:

```python luma_pagination.py
calendars_events_list = luma_api_client(
    name="calendars_events_list",
    args_schema=CalendarsEventsListRequest,
    method="GET",
    url_template="v1/calendars/events/list",
    pagination=Pagination(
        cursor_field="next_cursor",
        cursor_param="pagination_cursor",
        more_field="has_more",
    ),
)
```

<Note>
Pagination is declared on `calendars_events_list`, `events_guests_list`, `images_search`, `calendars_contacts_list`, `events_coupons_list`, `calendars_coupons_list`, `memberships_tiers_list`, `webhooks_list`, `organizations_calendars_list` and `organizations_events_list`. The other 64 take no cursor.
</Note>
{/* generated:wire end */}

Reads are `GET`s with query parameters and every write is a `POST`. Luma versions
each route on its own, so `/v1/` and `/v2/` sit side by side and the version is
part of each tool's URL. Failure is an HTTP status — `429` past the rate limit of
200 requests a minute per calendar key — and the ten list tools page on
`has_more`, sending `next_cursor` back as `pagination_cursor`.

## Limits

- **`null` cannot be sent.** Charter omits an unset field rather than sending
  `null`, so what Luma clears with `null` — an event's `font`, a registration
  question's library `source`, a calendar's `location`, a ticket type's
  `max_per_guest` — can be set through these tools but not cleared.
- **Uploading an image is two steps, and the second is not a tool.**
  `images_create_upload_url` returns an `upload_url` to `PUT` the bytes to, which
  is a file transfer to Luma's CDN rather than an API call.
- **`events_create` and `events_update` are large**, about 22KB of schema each,
  mostly themes, fonts and the thirteen kinds of registration question. A
  [projection](/tools/projections) keeps what an agent uses.
