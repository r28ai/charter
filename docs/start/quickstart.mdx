## Declare a tool

A tool for an API Charter has never seen, with your own rules on it. [httpbin.org](https://httpbin.org) stands in for the API: it echoes back the request it received, so everything on this page runs with no account.

<Steps>
  <Step title="Describe the arguments, and your rules">
    ```python refund.py
    from typing import Annotated, Literal

    from pydantic import BaseModel, Field, field_validator
    from charter import Body, Gloss


    class CreateRefund(BaseModel):
        charge: Annotated[str, Body()] = Field(description="The charge to refund.")
        amount: Annotated[int, Body(), Gloss("Cents, not dollars: $15.00 is 1500.")] = Field(
            gt=0, le=10_000, description="How much to refund, in the smallest currency unit."
        )
        reason: Annotated[Literal["duplicate", "requested_by_customer"], Body()] = Field(
            description="Why the charge is being refunded."
        )
        currency: Annotated[str, Body()] = Field("usd", description="Three-letter ISO currency code.")

        @field_validator("charge")
        @classmethod
        def a_charge(cls, value: str) -> str:
            if not value.startswith("ch_"):
                raise ValueError("refund a charge id (ch_...), not a customer or an invoice")
            return value
    ```

    <Note>
    [`Body()`](/reference/markers#body) says where each field goes in the request; [`Query()`](/reference/markers#query), [`Path()`](/reference/markers#path) and [`Header()`](/reference/markers#header) are the others. Everything else on the model is a rule of yours, on top of the API's: `le=10_000` caps a refund at $100, the `Literal` leaves out `"fraudulent"` although the API accepts it, and the validator is any check you can write in Python. The [`Gloss`](/reference/markers#gloss) is softer: a tip the model reads beside the field's own description, which nothing enforces.
    </Note>
  </Step>

  <Step title="Build a factory">
    The factory carries everything shared across the tools of one API: the base URL, the credential, and the conventions its wire format follows.

    ```python refund.py
    from charter import api_key_tool_factory

    payments = api_key_tool_factory(
        pack="payments",
        base_url="https://httpbin.org/anything/",
        api_key_headers={"Authorization": "Bearer sk_test_123"},
    )
    ```

    <Note>
    `pack` is a prefix for your tools' names, so this one reaches the model as `payments_refund`. For an API that takes an OAuth token, [`oauth_tool_factory`](/reference/factories#oauth_tool_factory) takes the same arguments and a credential provider.
    </Note>
  </Step>

  <Step title="Declare the tool">
    Point the arguments at an endpoint.

    ```python refund.py
    refund = payments(
        name="refund",
        description="Refund a charge.",
        method="POST",
        url_template="v1/refunds",
        args_schema=CreateRefund,
    )
    ```
  </Step>

  <Step title="Call it">
    ```python refund.py
    sent = refund.invoke({"charge": "ch_3MmlLr", "amount": 1500, "reason": "duplicate"})
    print(sent["method"], sent["url"])
    print(sent["json"])
    ```

    ```text
    POST https://httpbin.org/anything/v1/refunds
    {'amount': 1500, 'charge': 'ch_3MmlLr', 'currency': 'usd', 'reason': 'duplicate'}
    ```

    The key went out in the `Authorization` header and the model never saw it. A declaration also carries [wire format](/tools/transforms), [field policy](/boundary/mode-system) and [failure that arrives as HTTP 200](/tools/envelopes); [the wire contract](/tools/wire-contract) is where those go.
  </Step>
</Steps>

## Break a rule

Now the call a model gets wrong: a customer id where a charge belongs, $150, and a reason you ruled out.

```python refund.py
from charter import ToolValidationError

try:
    refund.invoke({"charge": "cus_9s6XKz", "amount": 15000, "reason": "fraudulent"})
except ToolValidationError as refused:
    print(refused)
```

```text
Validation error:
- **charge**: Value error, refund a charge id (ch_...), not a customer or an invoice (got 'cus_9s6XKz')
- **amount**: Input should be less than or equal to 10000 (got 15000)
- **reason**: Input should be 'duplicate' or 'requested_by_customer' (got 'fraudulent')
```

Nothing was sent. Every rule, the API's and yours, runs before any request, so a call that breaks one never reaches the API. In an agent, this message is what the model gets back as the tool's result, [naming each field and what it sent](/running/tool-validation-error-handling), so it can fix the call or stop. Charter never improvises. And since no request is made, every rule can be tested offline with plain unit tests.

## Pin a value, and see what the model sees

A pin removes a field from what the model sees and sends a fixed value on every call. Then print the boundary: it is computed from the same declarations the runtime executes, so it cannot drift from what actually happens.

```python refund.py
from charter import format_egress_map

refund_usd = refund.derived(name="refund_usd", pin={"currency": "usd"})
print(format_egress_map([refund_usd]))
```

```text
payments_refund_usd  (POST v1/refunds)
  visible to the model (3):
    + charge
    + amount
    + reason
  withheld (1):
    - currency  [pinned] = 'usd'
  pinned (1):
    = currency  'usd'
```

Commit that map and a change to it is a diff in review: a new tool, a widened field, a dropped pin. [The audit artifact](/boundary/egress-control#the-audit-artifact) has the CI check.

## Call a pack

A pack is the tools of one API, already declared the same way: a head start, not the limit. Configure the credential once and every tool in it is callable.

```python quickstart.py
import asyncio
import logging

from charter.packs import stripe

logging.basicConfig(format="%(message)s")
logging.getLogger("charter").setLevel(logging.INFO)

stripe.configure("sk_test_...")   # https://docs.stripe.com/keys


async def main():
    await stripe.customers_create.ainvoke({"email": "ada@example.com", "name": "Ada Lovelace"})


asyncio.run(main())
```

```
customers_create       POST v1/customers               200    782ms  ↑     33 B  ↓     661 B →     111 B  (83%)
```

Stripe takes an API key, so run this one first — a test key is enough. Look at the
sizes on that second line. Stripe's customer object comes back with twenty-three fields,
and the model read six.

You didn't configure that. Every pack tool ships with a response handler tailored to
its endpoint, there to keep your agent's context window small — which is why Stripe's
twenty-three-field customer reached the model as six. Write your own with
`tool.derived(name=..., response_handler=...)`, or turn the trimming off with `pass_through` and get
the response whole. The shape is yours either way:
[response handling](/reference/response-handling), and
[seeing the wire](/running/observability#seeing-the-wire) for the headers and body.

<Note>
**Gmail, Calendar, Sheets, Docs, Drive and Forms need a Google OAuth client
before their first call** — Google issues no API key for them. Making one is
ten minutes, once: [Set up Google](/auth/setup/google), a screenshot per
screen. Every other pack's credential, and the page that issues it, is on
[your own account](/auth/your-own-account).

Gmail and the other OAuth packs take a credential provider instead of a key:
`gmail.configure(StaticTokenProvider(access_token))` is fine for a one-time script and wrong
for a product, because the token expires in about an hour. See
[authorization servers](/auth/authorization-servers) for refresh against any OAuth 2.0
token endpoint, and [getting the grant](/auth/oauth-flow) for where the refresh token
comes from.
</Note>
