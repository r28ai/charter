A merchant connects a **store**, not an account, so the store is part of every
connection: the consent page, the token endpoint and the API host all live on
it. You register one app in Shopify's Dev Dashboard, each merchant installs it,
and you keep one token per store.

Only connecting a store you own? [Set up Shopify](/auth/setup/shopify) is
shorter, because no consent route is involved.

Every Shopify link below opens in a new tab, so this page stays where you left it.

<Steps>

<Step title="Create the app">

In the [Dev Dashboard](https://dev.shopify.com/dashboard), click **Create app**,
then name it under **Start from Dev Dashboard** and click **Create**. Merchants
see this name on the install screen.

<Frame>
  <img
    src="/images/setup/shopify/02-create-app.webp"
    alt="The Create an app page, with the app name Example App under Start from Dev Dashboard and a Create button."
  />
</Frame>

</Step>

<Step title="Set the app URL">

Shopify opens the app's first version. Under **URLs**, set **App URL** to your
product's address. This is where a merchant lands after installing, and when
the app opens from their admin.

<Frame>
  <img
    src="/images/setup/shopify/03-app-url.webp"
    alt="The Create a version page: app name Example App, and under URLs an App URL of https://app.example.com with Embed app in Shopify admin ticked."
  />
</Frame>

**Embed app in Shopify admin** loads your app inside the admin in an iframe.
Untick it unless your app is built for that.

</Step>

<Step title="Choose the scopes and add your redirect URL">

Further down, under **Access**, set the **Scopes** the tools need, either with
**Select scopes** or typed in and separated by commas. Below them, add your
callback route under **Redirect URLs**.

<Frame>
  <img
    src="/images/setup/shopify/06-redirect-urls.webp"
    alt="The version's Access section: a comma-separated list of scopes, an empty Optional scopes field, Use legacy install flow unticked, and https://app.example.com/oauth/shopify/callback under Redirect URLs."
  />
</Frame>

The scopes here are what Shopify grants on install, whatever the link asks
for. In a live install the link asked for `read_products`, and the install
screen listed every scope of the released version. The flow still sends the
list in its link, separated by commas, and the server constant on
[Shopify's provider page](/auth/providers/shopify) already declares that separator.

For development, a plain `http://localhost` callback works: Shopify accepted
`http://localhost:8765/callback` on a store installing the app for the first
time.

Leave **Use legacy install flow** unticked.

</Step>

<Step title="Release the version">

Click **Release** at the top of the page, then **Release** again in the dialog.
Nothing you set reaches a merchant until a version with it is released.

<Frame>
  <img
    src="/images/setup/shopify/07-release.webp"
    alt="The Release this new version dialog, with an optional version name and message and a Release button."
  />
</Frame>

</Step>

<Step title="Copy the client ID and secret">

Open the app's **Settings** and copy the **Client ID** and **Secret** from
**Credentials**.

<Frame>
  <img
    src="/images/setup/shopify/09-credentials.webp"
    alt="The app's Settings page: a Credentials panel with the client ID and a masked secret with reveal, copy and Rotate buttons."
  />
</Frame>

```bash
export SHOPIFY_CLIENT_ID=3c1f6e9a...
export SHOPIFY_CLIENT_SECRET=...
```

The secret also signs every request Shopify sends to your callback, and the
callback must check that signature. See the next step.

</Step>

<Step title="Connect a store">

Your "Connect Shopify" button asks for the merchant's store, then opens the
link that [`flow.authorize()`](/reference/oauth#oauth2flow-authorize) builds on
that store. The merchant reviews what the app needs and clicks **Install**.

<Frame>
  <img
    src="/images/setup/shopify/10-install.webp"
    alt="The merchant's Install app screen: a notice that the app hasn't been reviewed, the app Example App on My Store, the data it needs access to, and an Install button."
  />
</Frame>

*"This app hasn't been reviewed"* appears for any app that isn't listed on the
Shopify App Store. Listing it means going through Shopify's review.

At the callback, **check Shopify's `hmac` parameter before anything else**. It's
an HMAC-SHA256 of the other query parameters, keyed with your client secret.
Charter doesn't check it for you, because it's Shopify's own convention rather
than part of OAuth. Then exchange the code, with `exchange_params={"expiring": "1"}`
on the server so Shopify issues an expiring offline token and a refresh token.
Public apps must use that token for the GraphQL Admin API by January 1, 2027.
Store the shop and the grant against the user. The full shape, including the
per-call store and the refresh, is in the
[Shopify provider page](/auth/providers/shopify).

</Step>

</Steps>

## When it does not work

<AccordionGroup>
  <Accordion title="“The redirect_uri is not whitelisted”">
    The flow sent a URL that isn't under **Redirect URLs** in the active
    version. Add it, then release a new version, because an edit that isn't
    released doesn't count.

    On a store where the app is already installed, that may not be enough.
    In a live test, redirect URLs added in later released versions were all
    refused on such a store, over `http` and `https` alike, and with the app
    URL moved onto the same host. The URL the app had when it was installed
    was accepted. After uninstalling the app and installing it again through
    the flow, the new URL was accepted. So test a new URL on a store that
    hasn't installed the app, or reinstall it.
  </Accordion>
  <Accordion title="A scope you added is not granted">
    Scope changes reach a store only through a released version, and a store
    that installed earlier keeps its old grant until the merchant approves the
    new scopes. Release, then send the merchant through the link again.
  </Accordion>
  <Accordion title="403: “Required access: … access scope”">
    The grant doesn't include the scope that tool needs. Add the scope, release,
    and have the merchant reconnect.
  </Accordion>
</AccordionGroup>
