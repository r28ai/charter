<Note>
This page is for a product whose users each connect their own Stripe, Linear,
Notion or Google account — the way they would connect one to any SaaS app.
Connecting your own account to a script needs none of it:
[your own account](/auth/your-own-account) covers that.
</Note>

Every pack serves many users the same way. Configure it once, with a
[`SubjectProvider`](/reference/credentials#subjectprovider) that builds one
user's credential from what you stored when they connected. Then name the user
around each run:

```python many_users.py
from charter.auth import StaticTokenProvider, SubjectProvider, use_subject
from charter.packs import granola


# Yours to write: a user id in, that user's credential out.
async def granola_for(user_id: str):
    row = await db.keys.get(user_id, "granola")
    return StaticTokenProvider(row.api_key)


granola.configure(credential_provider=SubjectProvider(granola_for))

# Per request: whose account the tools act on.
with use_subject(request.user_id):
    await agent.ainvoke(...)
```

The tools are built once, at import, and shared by every user. The credential is
looked up below every adapter, so this works the same through MCP, LangChain, the
OpenAI tools interface and the Claude Agent SDK. No per-call header has to get
through the agent framework. A call with no user set raises instead of using
someone else's credential.

Serving users from more than one process? Where the provider rotates refresh
tokens (Stripe, Linear, Slack with rotation on), pass the client a function
that reads the stored grant rather than the refresh token itself, as the
[Linear](/auth/providers/linear) and [Stripe](/auth/providers/stripe) pages do. A copy goes stale the moment another
process refreshes, and Stripe's refresh also revokes the other processes'
access tokens: [More than one process](/auth/oauth-flow#more-than-one-process).

## Every pack

The *connect* column is what your user does. *Store* is what you keep
afterwards. *Provider* is what `for_user` returns.

| Pack | Connect | Store | Provider |
|---|---|---|---|
| Gmail, Calendar, Sheets, Docs, Drive, Forms | an OAuth link | a refresh token | `OAuth2Client(GOOGLE, ...)` — [Google](/auth/providers/google) |
| Slack | an OAuth link | the bot token, or a refresh token with rotation on | [Slack](/auth/providers/slack) |
| GitHub | an OAuth link | a refresh token, or the token of an app that does not expire them | `OAuth2Client(GITHUB, ...)` or [`StaticTokenProvider`](/reference/credentials#statictokenprovider) — [GitHub](/auth/providers/github) |
| Notion | an OAuth link | a refresh token | `OAuth2Client(NOTION, ...)` — [Notion](/auth/providers/notion) |
| Linear | an OAuth link, or a pasted personal key | a refresh token, or the key | `OAuth2Client(LINEAR, ...)` or `StaticTokenProvider` — [Linear](/auth/providers/linear) |
| Stripe | a Stripe App install link, or a pasted restricted key | a refresh token, or the key | `OAuth2Client(STRIPE_APPS, ...)` or `StaticTokenProvider` — [Stripe](/auth/providers/stripe) |
| Shopify | an OAuth link on the merchant's store | the store, and its token | `OAuth2Client(shopify_server(shop), ...)`, with `shop=` per call — [Shopify](/auth/providers/shopify) |
| Granola | a pasted API key | the key | `StaticTokenProvider` |
| Firecrawl, Tavily | nothing: these are services you pay for | your own key | `configure(api_key=...)`, once |

Every row takes the same [`OAuth2Flow`](/reference/oauth#oauth2flow), with a
different server constant. [Getting the grant](/auth/oauth-flow) has the full
shape: the two routes, `state`, PKCE, and what to store.

A pasted key needs no flow. Show a field, check the key with one call, and
store it the way you store any other secret.

Every OAuth row needs an app registered with the provider first: a redirect URL,
the scopes, and the client ID and secret the flow is built from. Each of these
has a screenshot for every screen:
[Google](/auth/apps/google), [Slack](/auth/apps/slack),
[GitHub](/auth/apps/github), [Linear](/auth/apps/linear),
[Notion](/auth/apps/notion), [Stripe](/auth/apps/stripe) and
[Shopify](/auth/apps/shopify).

## Each provider

Every OAuth provider has a page with its server constant, the flow and the
per-user client, what a refresh does, and how a user is disconnected.

### Linear

[Linear](/auth/providers/linear): refresh tokens that rotate with a 30-minute
grace, and a pasted personal key beside OAuth in one configuration.

### Stripe

[Stripe](/auth/providers/stripe): a Stripe App, its test link before you
publish, and a pasted restricted key as the other path.

### Notion

[Notion](/auth/providers/notion): a link that asks for no scopes, and what a
refresh does that Notion's docs leave out.

### Shopify

[Shopify](/auth/providers/shopify): a server per store, `shop=` per call, and
the expiring offline token Shopify now requires.

The original three are [Google](/auth/providers/google),
[Slack](/auth/providers/slack) and [GitHub](/auth/providers/github).

## Disconnecting a user

A "Disconnect" button revokes the grant at the provider, then deletes your
row. Deleting the row alone leaves the grant live, with every scope it was
given, and your app still listed on the user's account. The [`SubjectProvider`](/reference/credentials#subjectprovider)
the pack is configured with does both lookups for you:

```python disconnect.py {15}
from charter.auth import OAuth2Client, SubjectProvider

async def google_for(user_id: str):
    row = await db.grants.get(user_id, "google")
    return OAuth2Client(
        GOOGLE,  # the constant on the Google page
        client_id=os.environ["GOOGLE_CLIENT_ID"],
        client_secret=os.environ["GOOGLE_CLIENT_SECRET"],
        refresh_token=row.refresh_token,
    )

google_users = SubjectProvider(google_for)  # the one given to the Google packs' configure()

async def disconnect(user_id: str):
    await google_users.revoke(user_id)  # builds their client from the row, and revokes
    await db.grants.delete(user_id, "google")
```

[`revoke(user_id)`](/reference/credentials#subjectprovider) returns `False`
when the grant was already gone (the user removed the app on the provider's
side first) and raises only when the provider refused for some other reason.
Delete the row after it, not before: the client reads the grant from your
store to know what to revoke, and under [`refresh_lock`](/reference/oauth#refreshlock) it is the grant the
store holds, not one another process has already rotated.

What each server is sent is on its declaration, so the call is the same for
every pack. What each one does with it, measured live, is on its page:

- [Google](/auth/providers/google#disconnecting): the refresh token, which ends every grant your app holds for that account
- [Slack](/auth/providers/slack#disconnecting): `apps.uninstall`, which removes the installation
- [GitHub](/auth/providers/github#disconnecting): `DELETE /applications/{client_id}/grant`, with an access token
- [Linear](/auth/providers/linear#disconnecting): the refresh token, with the `token_type_hint` Linear needs
- [Notion](/auth/providers/notion#disconnecting): the access token; Notion answers `200` to any token
- [Shopify](/auth/providers/shopify#disconnecting): uninstalls the app, and with it every grant on that store
- [Stripe](/auth/providers/stripe#disconnecting): uninstalls the Stripe App, through the App Installs API

A pasted key (Linear's personal key, a Stripe restricted key, Granola) was
made by the user, and only they can delete it. Delete the row.

## What stays yours

The same line as everywhere in Charter's auth. The consent routes, the session
that holds `state` and the PKCE verifier, the database the grants live in, and
any encryption at rest are your application's. Charter builds the link, exchanges
the code, refreshes the grant, revokes it when the user disconnects, and puts
the right user's credential on each call.
[Security invariants](/auth/oauth-flow#security-invariants) lists the rules the
callback has to keep.
