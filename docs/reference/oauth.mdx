Everything on this page is imported from `charter.auth`, not `charter`.

OAuth 2.0 declared rather than wrapped: a server is a frozen declaration in RFC
8414's vocabulary, a client refreshes a grant you already hold, a flow covers
the two steps of obtaining one that are protocol rather than product, and a
revocation is the one step of ending it.

The host keeps the callback route, the session, and storage. Charter signs
nothing, so JWT-bearer and service-account grants are out of scope.

## `OAuth2Server`

```python
@dataclass(frozen=True)
class OAuth2Server:
    token_endpoint: str
    token_endpoint_auth_method: TokenEndpointAuthMethod = "client_secret_post"
    issuer: Optional[str] = None
    authorization_endpoint: Optional[str] = None
    authorization_params: Mapping[str, str] = field(default_factory=dict)
    uses_scopes: bool = True
    scope_separator: str = " "
    token_request_format: Literal["form", "json"] = "form"
    default_expires_in: Optional[int] = None
    exchange_params: Mapping[str, str] = field(default_factory=dict)
    dead_grant_errors: tuple[str, ...] = ()
    revocation: Optional[Revocation] = None
```

<ParamField path="token_endpoint" type="str" required>
  Where the form POST goes. Empty raises [`DeclarationError`](/reference/errors#declarationerror).
</ParamField>

<ParamField path="token_endpoint_auth_method" type='"client_secret_post" | "client_secret_basic" | "secret_key_basic"' default='"client_secret_post"'>
  How the client authenticates (RFC 6749 §2.3.1). `client_secret_post` puts the
  credentials in the form body, which is what Google, GitHub and most APIs
  expect; `client_secret_basic` puts them in an HTTP Basic header.
  `secret_key_basic` is outside the RFC: the client secret alone is the Basic
  username, with no password and no client ID, which is how Stripe's token
  endpoint takes your secret key. Any other value raises
  [`DeclarationError`](/reference/errors#declarationerror).
</ParamField>

<ParamField path="issuer" type="Optional[str]" default="None">
  The issuer identifier, when the server publishes one.
</ParamField>

<ParamField path="authorization_endpoint" type="Optional[str]" default="None">
  Where a user is sent for consent. Optional: a declaration without one is still
  a working token-refresh-only server, and
  `OAuth2Flow.authorize` raises with instructions if
  you start a consent flow against one.
</ParamField>

<ParamField path="authorization_params" type="Mapping[str, str]" default="{}">
  Extra authorization-URL parameters this registration needs. The one field
  discovery can never fill in — Google without
  `{"access_type": "offline", "prompt": "consent"}` returns no refresh token and
  reports no error. Normalised to a read-only, key-sorted mapping, so the
  declaration stays frozen all the way down.
</ParamField>

<ParamField path="uses_scopes" type="bool" default="True">
  `False` for a server whose permissions are set where the app is registered —
  Notion's capabilities, a Stripe App's manifest. `OAuth2Flow.authorize` then
  takes no scopes and sends no `scope`, and raises if given some, since they
  would be ignored.
</ParamField>

<ParamField path="scope_separator" type="str" default='" "'>
  How the consent link joins scopes. RFC 6749 §3.3 says a space; Linear and
  Shopify document a comma.
</ParamField>

<ParamField path="token_request_format" type='"form" | "json"' default='"form"'>
  How the token endpoint wants its body, for the exchange and every refresh.
  The RFC's form unless the server documents otherwise; Notion's takes only
  JSON.
</ParamField>

<ParamField path="default_expires_in" type="Optional[int]" default="None">
  The access token's lifetime in seconds, for a server that documents one but
  leaves `expires_in` out of its token response. Stripe's tokens last an hour
  and its response never says so. Without this, a token with no `expires_in`
  is kept until the API refuses it, and that call fails. With it, the token is
  renewed shortly before it lapses. An `expires_in` in the response always
  wins. Anything but a positive whole number raises `DeclarationError`.
</ParamField>

<ParamField path="exchange_params" type="Mapping[str, str]" default="{}">
  Vendor fields for the code exchange, as `authorization_params` are for the
  consent link. Shopify asks for its expiring offline token, the one public
  apps must use for the GraphQL Admin API, with `{"expiring": "1"}`. Sent with
  the exchange only, never with a refresh. A field the exchange owns
  (`grant_type`, `code`, `redirect_uri`, `code_verifier`, `client_id`,
  `client_secret`, `refresh_token`) raises `DeclarationError`.
</ParamField>

<ParamField path="dead_grant_errors" type="tuple[str, ...]" default="()">
  Error codes, besides RFC 6749's `invalid_grant`, that the server uses to say
  a grant is gone. Slack answers a spent refresh token with
  `invalid_refresh_token` and an uninstalled app with `token_revoked`, both in
  an HTTP 200; GitHub uses `bad_refresh_token`, and Linear `invalid_request`. A declared code is handled
  like `invalid_grant`: a 60-second cool-down, one more read of a
  [`GrantLoader`](#grantloader), and a `CredentialError` whose `reauthorize` is
  true. `invalid_grant` always counts. A bare string, or an empty or
  non-string code, raises `DeclarationError`.
</ParamField>

<ParamField path="revocation" type="Optional[Revocation]" default="None">
  How the server ends a grant, for a "disconnect" button: a
  [`Revocation`](#revocation), which is RFC 7009 unless it says otherwise.
  [`OAuth2Client.revoke`](#attributes-and-methods) and
  [`revoke_token`](#revoke_token) send it. `None` means the server documents
  no way to; Stripe Apps is the case. Anything but a `Revocation`, a bare URL
  included, raises `DeclarationError`, and so does a revocation sending its
  token in the `Authorization` header to a server whose client authentication
  uses that header too.
</ParamField>

### `OAuth2Server.discover`

```python
@classmethod
async def discover(
    cls,
    issuer: str,
    *,
    client: Optional[httpx.AsyncClient] = None,
    timeout: int = 20,
) -> OAuth2Server: ...
```

Read the server's own metadata and build a declaration from it. Tries
`.well-known/openid-configuration`, then `.well-known/oauth-authorization-server`.
This is the path for anything an enterprise runs — Okta, Entra ID, Auth0,
Keycloak and Ping all publish one.

`token_endpoint_auth_method` is chosen from
`token_endpoint_auth_methods_supported`, preferring `client_secret_post`. A
document with no `token_endpoint`, or advertising neither usable method, raises
[`CredentialError`](/reference/errors#credentialerror); so does exhausting both well-known paths, with every attempt
named in the message.

A `revocation_endpoint` in the document becomes a [`Revocation`](#revocation).
Its auth method is the token endpoint's when
`revocation_endpoint_auth_methods_supported` allows it or is absent, and
otherwise the first of `client_secret_post`, `client_secret_basic` and `none`
the list names. A list naming none of them leaves `revocation` unset rather
than failing discovery.

The one network call in this library that is not a tool call.

## `Revocation`

```python
@dataclass(frozen=True)
class Revocation:
    endpoint: str
    token_type: Literal["refresh_token", "access_token"] = "refresh_token"
    auth_method: Optional[RevocationAuthMethod] = None
    token_field: Optional[str] = None
    token_header: Optional[str] = None
    http_method: Literal["POST", "DELETE"] = "POST"
    request_format: Optional[Literal["form", "json"]] = None
    gone_errors: tuple[str, ...] = ()
    gone_statuses: tuple[int, ...] = ()
```

How a server ends a grant, declared on [`OAuth2Server`](#oauth2server) as
`revocation`. The defaults are [RFC 7009](https://www.rfc-editor.org/rfc/rfc7009):
one POST carrying the refresh token as `token`, authenticated and encoded the
way the token endpoint is. Revoking the refresh token ends the grant and every
access token issued from it, and the app leaves the user's list of connected
apps. Every other field is a vendor's departure, written down as the token
endpoint's are. Each provider page carries its declaration.

<ParamField path="endpoint" type="str" required>
  Where the request goes. `{client_id}` is replaced with the client ID, since
  GitHub's endpoint is per registration. Empty raises `DeclarationError`.
</ParamField>

<ParamField path="token_type" type='"refresh_token" | "access_token"' default='"refresh_token"'>
  Which token the endpoint takes. `"access_token"` is for an endpoint that ends
  the whole grant given any live access token: GitHub's
  `DELETE /applications/{client_id}/grant`, Slack's `apps.uninstall`,
  Shopify's `api_permissions/current.json`. A client sends its cached token,
  refreshing first if it has lapsed.
</ParamField>

<ParamField path="auth_method" type="Optional[RevocationAuthMethod]" default="None">
  How the client authenticates, when it differs from the token endpoint.
  `None` inherits `token_endpoint_auth_method`; `"none"` sends no client
  credentials, for an endpoint documented to take the token alone (Google,
  Linear).
</ParamField>

<ParamField path="token_field" type="Optional[str]" default="None">
  The body field carrying the token, `token` when left as `None`. GitHub
  names it `access_token`.
</ParamField>

<ParamField path="token_header" type="Optional[str]" default="None">
  Send the token as the request's own credential instead. `"Authorization"`
  sends `Bearer <token>`; any other header gets the bare token, as Shopify's
  `X-Shopify-Access-Token` does. Requires `token_type="access_token"`, and
  cannot be combined with `token_field`; either mistake raises
  `DeclarationError`.
</ParamField>

<ParamField path="http_method" type='"POST" | "DELETE"' default='"POST"'>
  `DELETE` for GitHub and Shopify.
</ParamField>

<ParamField path="request_format" type='Optional["form" | "json"]' default="None">
  The body's format, inheriting `token_request_format` when `None`. GitHub's
  API takes JSON where its token endpoint takes a form. A request with nothing
  to put in a body sends none.
</ParamField>

<ParamField path="gone_errors" type="tuple[str, ...]" default="()">
  Error codes with which the server says the token was already dead. RFC
  7009's `invalid_token`, `invalid_grant` and the server's
  `dead_grant_errors` always count. Slack declares `invalid_auth`,
  `account_inactive` and `token_expired`. A bare string raises
  `DeclarationError`.
</ParamField>

<ParamField path="gone_statuses" type="tuple[int, ...]" default="()">
  Statuses that say the same, for a server that answers without an OAuth error
  code: GitHub's `422`, Linear's `400`. A `401` always counts when the token is
  the request's own credential. Anything but 4xx codes raises
  `DeclarationError`.
</ParamField>

A token already dead is not a failure: for a disconnect it is the outcome
asked for, so it returns `False` rather than raising. Any other refusal raises
`CredentialError`, with the error code and description and the token and
client secret redacted from both.

## `revoke_token`

```python
async def revoke_token(
    server: OAuth2Server,
    *,
    refresh_token: Optional[str] = None,
    access_token: Optional[str] = None,
    client_id: Optional[str] = None,
    client_secret: Optional[str] = None,
    timeout: int = 20,
    client: Optional[httpx.AsyncClient] = None,
) -> bool: ...
```

Revoke a grant held as a string, without building a client: a Slack bot token
from an app without rotation, a classic GitHub OAuth token, or a disconnect
handler holding a stored row. [`OAuth2Client.revoke`](#attributes-and-methods)
calls this.

Pass what you have. A server that revokes by refresh token is sent
`refresh_token` when given, since that ends the whole grant, and
`access_token` otherwise. One declared with `token_type="access_token"` needs
a live `access_token`, and raises `CredentialError` without one.
`client_id` and `client_secret` are needed wherever the client authenticates,
or `{client_id}` is in the endpoint.

Returns `True` when the server confirmed the revocation, and `False` when it
said the token was already dead. Raises `DeclarationError` when the server
declares no `revocation`, and `CredentialError` for any other refusal.

## `OAuth2Client`

```python
class OAuth2Client:
    def __init__(
        self,
        server: OAuth2Server,
        *,
        client_id: str,
        client_secret: str,
        refresh_token: Optional[Union[str, GrantLoader]] = None,
        grant: Grant = "refresh_token",
        scope: Optional[str] = None,
        on_refresh: Optional[OnRefresh] = None,
        refresh_lock: Optional[RefreshLock] = None,
        leeway_seconds: int = 90,
        timeout: int = 20,
        client: Optional[httpx.AsyncClient] = None,
    ) -> None: ...
```

A [`CredentialProvider`](/reference/credentials#credentialprovider) backed by a
token endpoint. Holds one grant — one end user, or one machine identity. Serve
many users by wrapping it in
[`SubjectProvider`](/reference/credentials#subjectprovider).

<ParamField path="server" type="OAuth2Server" required>
  The declaration to refresh against. Anything else raises `TypeError`.
</ParamField>

<ParamField path="client_id" type="str" required>
  Your registration's client id. Empty raises `CredentialError`.
</ParamField>

<ParamField path="client_secret" type="str" required>
  Your registration's client secret. Empty raises `CredentialError`.
</ParamField>

<ParamField path="refresh_token" type="Optional[str | GrantLoader]" default="None">
  The grant to renew. Required for the `refresh_token` grant — omitting it
  raises `CredentialError` saying that obtaining a grant is your application's
  flow.

  A [`GrantLoader`](#grantloader) instead of a string reads your store whenever
  the client's token is due or refused: right before a refresh, and once more
  if the server answers `invalid_grant` or a code in `dead_grant_errors`. Use
  one when more than one process serves the same user and the server rotates
  refresh tokens. A string is a
  copy, and it goes stale as soon as another process refreshes:
  [More than one process](/auth/oauth-flow#more-than-one-process). A loader
  that raises, or returns no refresh token, raises `CredentialError`.
</ParamField>

<ParamField path="grant" type='"refresh_token" | "client_credentials"' default='"refresh_token"'>
  `refresh_token` is the agent acting for an end user; `client_credentials` is
  the agent acting as itself. These are the two grants that are a plain form
  POST; any other value raises `ValueError`.
</ParamField>

<ParamField path="scope" type="Optional[str]" default="None">
  Space-separated scopes to send with the token request, when the server wants
  them narrowed.
</ParamField>

<ParamField path="on_refresh" type="Optional[Callable[[Credentials, Optional[str]], None | Awaitable[None]]]" default="None">
  Called after every successful refresh with the new credentials and the refresh
  token to store next time — which may be a new one, since some servers rotate
  on every use. This is where persistence lives. A callback that raises is
  logged at WARNING and does not fail the call the token was fetched for.
</ParamField>

<ParamField path="refresh_lock" type="Optional[RefreshLock]" default="None">
  A lock across processes for this grant, as a function returning an async
  context manager. The client holds it while it reads the store, refreshes if
  it still has to, and runs `on_refresh`, so the next holder reads that result
  instead of refreshing again. Mandatory against a server with reuse
  detection, where two processes presenting one refresh token revoke the
  grant, and against one whose refresh retires the previous access token,
  where they revoke each other's tokens and calls fail:
  [A lock around the refresh](/auth/oauth-flow#a-lock-around-the-refresh).
  Requires `refresh_token` to be a [`GrantLoader`](#grantloader), or raises
  `ValueError`. A lock that cannot be taken raises `CredentialError`.
</ParamField>

<ParamField path="leeway_seconds" type="int" default="90">
  How early to renew. Capped at half the lifetime the server granted, so a
  60-second token does not refresh on every call.
</ParamField>

<ParamField path="timeout" type="int" default="20">
  Timeout for the token request.
</ParamField>

<ParamField path="client" type="Optional[httpx.AsyncClient]" default="None">
  Reuse an HTTP client for token requests. When omitted, one is created and
  closed per request.
</ParamField>

The access token is cached in memory until the leeway window and written
nowhere. Concurrent callers wait on a single refresh: some servers invalidate
the previous refresh token on use, so twelve parallel tool calls each firing
their own refresh would poison eleven of them.

An `invalid_grant` answer, or a code the server declares in
`dead_grant_errors`, marks the grant dead for 60 seconds and re-raises the same
error without asking the server again — one revoked user must not become a
stream of requests against an endpoint that rate-limits per client. The error's
`reauthorize` is true, which is the signal to show the user a reconnect button.

### Attributes and methods

<ResponseField name="server" type="OAuth2Server">
  The declaration passed in.
</ResponseField>

<ResponseField name="grant" type='"refresh_token" | "client_credentials"'>
  Which grant this client uses.
</ResponseField>

<ResponseField name="scope" type="Optional[str]">
  The scope string sent with token requests.
</ResponseField>

<ResponseField name="leeway_seconds" type="int">
  The configured leeway, before the lifetime cap is applied.
</ResponseField>

<ResponseField name="refresh_token" type="Optional[str]">
  The *current* refresh token, which is not necessarily the one passed in: a
  server that rotates hands back a new one on every refresh and Charter adopts
  it.
</ResponseField>

<ResponseField name="get_credentials(provider)" type="Credentials">
  The provider protocol. Returns the cached token, or refreshes.
</ResponseField>

<ResponseField name="reset()" type="None">
  Forget the cached token and any dead-grant cool-down. Call it after
  re-authorizing, if you are reusing the client rather than building a new one.
</ResponseField>

<ResponseField name="invalidate(credentials)" type="None">
  Forget the cached token if it is `credentials.token` — called by the runtime
  when the API refuses it, so the next call fetches a new one rather than
  sending a revoked token until its expiry. A token that has already been
  replaced is left alone, and the grant and its cool-down are untouched.
</ResponseField>

<ResponseField name="revoke()" type="bool">
  End the grant at the server, then stop using it: the disconnect button.
  Sends the server's [`Revocation`](#revocation) with the current refresh
  token, or with a live access token where the server takes one, refreshing
  first if the cached one lapsed. With a [`GrantLoader`](#grantloader) the
  store is read first, under `refresh_lock`, so the grant revoked is the one
  stored and not one another process has rotated away from. A refresh in
  flight in this process finishes first, for the same reason.

  `True` when the server confirmed it, `False` when the grant was already
  gone. Either way the client then refuses to refresh: `get_credentials`
  raises a `CredentialError` whose `reauthorize` is true, without asking the
  token endpoint, until `reset()` or until the loader returns a different
  refresh token. A `client_credentials` client revokes its cached token and
  only drops it. Any other refusal raises `CredentialError` and leaves the
  client working. No `revocation` on the server raises `DeclarationError`
  before any request. Deleting the stored grant is yours, afterwards.
</ResponseField>

### `OAuth2Client.from_grant`

```python
@classmethod
def from_grant(
    cls,
    server: OAuth2Server,
    grant: TokenGrant,
    *,
    client_id: str,
    client_secret: str,
    on_refresh: Optional[OnRefresh] = None,
    **kwargs: Any,
) -> OAuth2Client: ...
```

A client seeded from a fresh `exchange`: the grant's
access token pre-fills the cache, so the first tool call after connecting spends
no refresh. A grant carrying no refresh token is refused with `CredentialError`
— for a one-shot access token, use
[`StaticTokenProvider`](/reference/credentials#statictokenprovider).

## `OAuth2Flow`

```python
class OAuth2Flow:
    def __init__(
        self,
        server: OAuth2Server,
        *,
        client_id: str,
        client_secret: str,
        redirect_uri: str,
        timeout: int = 20,
        client: Optional[httpx.AsyncClient] = None,
    ) -> None: ...
```

The stateless half of obtaining a grant. Registration facts live here —
`client_id`, `client_secret`, `redirect_uri` — beside the server declaration,
which holds what the server *is*.

<ParamField path="redirect_uri" type="str" required>
  The exact callback URL registered with the authorization server, never one
  built from user input. Empty raises `CredentialError`.
</ParamField>

Nothing is remembered between `authorize()` and `exchange()`: the state and the
PKCE verifier are handed to you and taken back, because only your framework
knows which browser is which.

### `OAuth2Flow.authorize`

```python
def authorize(
    self,
    scopes: Iterable[str] = (),
    *,
    state: Optional[str] = None,
    login_hint: Optional[str] = None,
    pkce: bool = True,
    extra_params: Optional[Mapping[str, str]] = None,
) -> AuthorizationRequest: ...
```

Build the authorization URL (RFC 6749 §4.1.1). Pure — no I/O, no state.

<ParamField path="scopes" type="Iterable[str]" default="()">
  What to ask for. Empty raises `CredentialError`: an authorization request for
  nothing is a bug upstream. [`scopes_for`](#scopes_for) derives this from a
  tool set. Against a server declared with `uses_scopes=False` it is the other
  way round: leave it empty, and no `scope` is sent.
</ParamField>

<ParamField path="state" type="Optional[str]" default="None">
  Your own CSRF token. Generated with `secrets.token_urlsafe(32)` when omitted.
</ParamField>

<ParamField path="login_hint" type="Optional[str]" default="None">
  Which account to pre-select on the consent screen.
</ParamField>

<ParamField path="pkce" type="bool" default="True">
  S256 PKCE (RFC 7636). `False` exists for the rare server that rejects unknown
  parameters, and is never the recommended path.
</ParamField>

<ParamField path="extra_params" type="Optional[Mapping[str, str]]" default="None">
  Per-request additions, merged last.
</ParamField>

Parameters merge later-wins: the standard set, then the server's
`authorization_params`, then `extra_params`. Neither map may set `client_id`,
`redirect_uri`, `state` or anything starting with `code_challenge` — identity
and the CSRF/PKCE material belong to the flow, and an attempt raises
`ValueError` naming the source. A server with no `authorization_endpoint` raises
`CredentialError`.

`scope` is encoded with `%20` rather than `+`, which some servers reject.

### `OAuth2Flow.exchange`

```python
async def exchange(
    self,
    code: str,
    *,
    code_verifier: Optional[str] = None,
    expect_refresh_token: bool = True,
) -> TokenGrant: ...
```

Trade the callback's code for tokens (RFC 6749 §4.1.3). One form POST to the
same token endpoint the refresh uses.

<ParamField path="code" type="str" required>
  The authorization code from the callback. Empty raises `CredentialError`.
</ParamField>

<ParamField path="code_verifier" type="Optional[str]" default="None">
  The verifier `authorize()` returned, when PKCE was used.
</ParamField>

<ParamField path="expect_refresh_token" type="bool" default="True">
  Raise `CredentialError` when the server returns no refresh token. This is the
  silent failure of the whole flow — the exchange succeeds, the access token
  works, and the integration dies within the hour. Pass `False` only for a
  server that genuinely never issues one.
</ParamField>

Codes are single-use, so a failed exchange is never retried and no cooldown
applies; restarting the flow is the host's move.

## `TokenGrant`

```python
class TokenGrant(BaseModel):
    access_token: str
    refresh_token: Optional[str] = None
    expires_at: Optional[datetime] = None
    scopes: list[str] = Field(default_factory=list)
    raw: Dict[str, Any] = Field(default_factory=dict)
```

What a code exchange returned — the one moment a refresh token is visible.

<ResponseField name="access_token" type="str">
  Valid now, typically for an hour.
</ResponseField>

<ResponseField name="refresh_token" type="Optional[str]">
  What you persist. `None` when the server issued none and
  `expect_refresh_token=False`.
</ResponseField>

<ResponseField name="expires_at" type="Optional[datetime]">
  Derived from `expires_in`, or `None` when the server sent none.
</ResponseField>

<ResponseField name="scopes" type="list[str]">
  What the server says was actually granted, which is not always what was asked
  for: some consent screens let a user deselect.
</ResponseField>

<ResponseField name="raw" type="Dict[str, Any]">
  The untouched response body, for vendor extras.
</ResponseField>

Both `repr` and `str` mask the tokens, so printing a grant does not put a secret
in a log line.

This is deliberately not
[`Credentials`](/reference/credentials#credentials): that is the injection
currency, handed out on every tool call. A grant is what you persist once.

## `states_match`

```python
def states_match(expected: str, received: str) -> bool: ...
```

Whether the callback's `state` is the one `authorize()` issued. Compares in
constant time, so the CSRF check is one obvious call rather than a plain `==`
that leaks how many leading characters matched.

Verifying `state` at the callback is the host's job: it is what keeps an
attacker from splicing their code into your user's session.

## `scopes_for`

```python
def scopes_for(tools: Iterable[Tool]) -> list[str]: ...
```

The scopes an authorization request must cover to run these tools, read from the
`scopes` metadata each was declared with and deduped in first-seen order.

```python
from charter.auth import scopes_for
from charter.packs import gcalendar, gmail

consent = scopes_for([*gmail.TOOLS, *gcalendar.TOOLS])
assert "https://www.googleapis.com/auth/gmail.modify" in consent
```

The consent screen is then exactly what the agent can do, kept in lockstep with
the tool set instead of maintained beside it.

## Types in these signatures

The aliases the signatures above are declared in. They are exported from
`charter.auth` so a host writing its own wrapper can name them without importing
from a submodule.

## `Grant`

```python
Grant = Literal["refresh_token", "client_credentials"]
```

Which OAuth 2.0 grant an `OAuth2Client` uses. `"refresh_token"` acts for a user
who consented; `"client_credentials"` acts as the application itself, with no
user and so no refresh token to store.

## `RevocationAuthMethod`

```python
RevocationAuthMethod = Literal["client_secret_post", "client_secret_basic", "secret_key_basic", "none"]
```

How the client authenticates to a revocation endpoint: the token endpoint's
methods, plus `none` for an endpoint that takes the token alone. Google's is
documented with nothing but `token`, so its declaration sends the client secret
nowhere it is not asked for.

## `TokenEndpointAuthMethod`

```python
TokenEndpointAuthMethod = Literal["client_secret_post", "client_secret_basic", "secret_key_basic"]
```

How the client authenticates to the token endpoint — credentials in the form
body, in an HTTP Basic header, or (`secret_key_basic`, Stripe) the secret alone
as the Basic username. [RFC 8414](https://www.rfc-editor.org/rfc/rfc8414)
names this field, and a server's own metadata usually announces which it wants;
`OAuth2Server.discover` reads it for you.

Getting it wrong is a silent-shaped failure: the server answers
`invalid_client`, which reads like a wrong secret rather than a wrong envelope.

## `OnRefresh`

```python
OnRefresh = Callable[[Credentials, Optional[str]], Union[None, Awaitable[None]]]
```

Called after every successful refresh, with the new credentials and the refresh
token to store next time, which may be a new one. Sync or async; both are
awaited correctly.

This is where a rotated refresh token gets persisted. A server that rotates
hands you a new one in the refresh response and invalidates the old immediately,
so a host that does not write it down is one restart away from a dead grant.

```python
async def store(credentials: Credentials, refresh_token: Optional[str]) -> None:
    if refresh_token:
        await db.grants.put("user_1042", "google", refresh_token)

client = OAuth2Client(GOOGLE, client_id=..., client_secret=..., refresh_token=...,
                      on_refresh=store)
```

An `on_refresh` that raises is logged as a warning and does not fail the call:
the token is still good for this process. So a callback with the wrong
signature fails quietly, and the rotated token is never stored.

## `GrantLoader`

```python
GrantLoader = Callable[[], Union[str, TokenGrant, Awaitable[Union[str, TokenGrant]]]]
```

Passed as `refresh_token`, it reads a grant from your store, where `on_refresh`
wrote it. Return the refresh token alone, and no process refreshes with one
another has already spent. Return a [`TokenGrant`](#tokengrant) with the access
token and its expiry too, and a process whose own token is due takes the stored
one instead of refreshing, so one refresh serves every process. That is
required against Stripe, whose refresh revokes the previous access token within
seconds. A stored token is skipped when it is inside the renewal window, or is
the one the API just refused.

```python
async def stored_grant() -> TokenGrant:
    row = await db.grants.get("user_1042", "stripe")
    return TokenGrant(access_token=row.access_token, refresh_token=row.refresh_token,
                      expires_at=row.expires_at)

async def store(credentials: Credentials, refresh_token: Optional[str]) -> None:
    await db.grants.put("user_1042", "stripe", refresh_token,
                        access_token=credentials.token, expires_at=credentials.expires_at)

client = OAuth2Client(STRIPE_APPS, client_id=..., client_secret=...,
                      refresh_token=stored_grant, on_refresh=store)
```

## `RefreshLock`

```python
RefreshLock = Callable[[], AsyncContextManager[Any]]
```

Passed as `refresh_lock`, it takes a lock scoped to one grant, across every
process that serves it: a Postgres advisory lock, a Redis lock. Called once per
refresh, and held from the read of the store to the end of `on_refresh`.

```python
def grant_lock(user_id: str, provider: str) -> RefreshLock:
    @asynccontextmanager
    async def held():
        async with pool.acquire() as conn, conn.transaction():
            await conn.execute("SELECT pg_advisory_xact_lock(hashtext($1))", f"{user_id}:{provider}")
            yield

    return held
```
